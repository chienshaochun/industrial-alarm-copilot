# ALPI 資料契約

## 1. 目的

本文件定義 `data/raw/alarms.csv` 在 Industrial Alarm Copilot 中的讀取、驗證與正規化規則。後續的探索分析、事件分組、檢索與預測都必須遵守同一份契約，避免不同模組對同一欄資料產生不同解讀。

原始檔視為唯讀來源，不直接修改或覆寫。所有清理結果都必須另存為可重新產生的衍生資料。

## 2. 原始資料結構

每一列代表設備記錄的一次警報，包含三個欄位：

| 原始欄位 | 預期格式 | 專案中的名稱 | 意義 |
| --- | --- | --- | --- |
| `timestamp` | 可解析的日期時間字串 | `timestamp` | 警報被記錄的時間 |
| `alarm` | 整數型識別碼 | `alarm_code` | 匿名警報代碼 |
| `serial` | 整數型識別碼 | `machine_id` | 匿名設備代碼 |

`alarm` 與 `serial` 雖然在 CSV 中以數字表示，但其用途是識別類別，而不是可直接計算大小的連續數值。例如，警報 `139` 不代表比警報 `31` 更嚴重，設備 `4` 也不代表其物理量大於設備 `3`。

資料來源沒有提供時區，因此 `timestamp` 保留為無時區日期時間；專案不得自行假設它是 UTC 或特定工廠的當地時間。

## 3. 目前資料集基準

對原始 CSV 的初步掃描結果如下：

| 項目 | 結果 |
| --- | ---: |
| 資料列數 | 444,834 |
| 設備數 | 20 |
| 不同警報代碼數 | 154 |
| 最早時間 | 2019-02-21 10:16:18.130 |
| 最晚時間 | 2020-06-17 03:53:51.885 |
| 缺失值 | 0 |
| 無法解析的欄位值 | 0 |
| 完全相同列 | 83 |

這些數字是目前檔案的資料品質基準，不代表未來所有相容資料都必須具有相同筆數。

## 4. 驗證規則

載入器必須檢查：

- 欄位集合必須恰好包含 `timestamp`、`alarm`、`serial`；
- 三個必要欄位均不可缺值；
- `timestamp` 必須能完整轉換為日期時間；
- `alarm` 與 `serial` 必須能完整轉換為整數識別碼；
- 每列必須保留可回溯原始位置的 `source_row`；
- 不因全檔時間未遞增而判定資料無效，但必須在正規化時排序；
- 完全相同列不得靜默刪除，必須加上重複標記。

缺少欄位、缺值或型別無法解析屬於阻止 pipeline 繼續執行的錯誤。順序不一致與重複列屬於需要記錄的資料品質現象。

## 5. 順序規則

原始檔依設備分成 20 個區塊，因此整份 CSV 並非全域時間排序；目前共觀察到 19 次跨設備區塊造成的時間回退。同一設備內的資料則依時間遞增。

正規化事件必須使用下列鍵進行穩定排序：

1. `machine_id`
2. `timestamp`
3. `source_row`

`source_row` 是原始 CSV 表頭後從 0 開始計算的資料列位置。當同一設備有多筆相同時間的警報時，它負責保留原始先後順序，使處理結果可以重現。

## 6. 重複資料政策

若兩列的 `timestamp`、`alarm` 與 `serial` 完全相同，目前無法從資料本身判斷它是：

- 真實的短時間重複觸發；
- 持續警報造成的重複記錄；
- alarm flooding；
- 資料收集或匯出時產生的重複列。

因此，原始事件視圖保留所有列，並提供：

| 衍生欄位 | 意義 |
| --- | --- |
| `source_row` | 原始資料列位置 |
| `is_exact_duplicate` | 該列是否屬於完全相同列群組 |
| `duplicate_group_size` | 相同列在原始檔中的出現次數 |

任何去重或合併操作都只能發生在明確命名的衍生視圖中，且必須保留被合併的數量，不得覆寫原始資料。

## 7. 兩種事件視圖

### 7.1 完整事件視圖

保留每一筆原始記錄，用於資料品質分析、警報密度、alarm flooding 與事件次數統計。這是主要且可追溯的資料視圖。

### 7.2 序列轉移視圖

在同一設備、排序後的序列中，允許將連續相同的 `alarm_code` 折疊成一段，並保留開始時間、結束時間與重複次數。此視圖適合馬可夫轉移或下一警報預測，避免連續重複代碼只是在描述同一個持續狀態。

是否折疊必須是模型或分析流程的明確參數。完整事件視圖與序列轉移視圖的評估結果不得混在一起比較而不加註明。

## 8. 時間洩漏規則

- 資料切分必須在每台設備內依時間進行，不使用隨機打散；
- 驗證集與測試集的事件不得參與訓練期統計量的估計；
- 對某個時間點進行檢索或預測時，只能使用該時間點以前可取得的資料；
- 相同 timestamp 的事件若跨越切分邊界，必須整組放在同一側，避免同時出現在過去與未來。

## 9. 解讀限制

ALPI 提供匿名警報代碼、設備代碼與發生時間，但沒有警報文字、嚴重程度、clear/reset 狀態、感測器數值、維修紀錄或停機標籤。因此本專案可以描述警報的頻率、順序與歷史關聯，但不能只根據此資料宣稱特定零件故障、真正根因或維修方式。

從物理意義來看，一列資料是「某台設備在某個時間留下了一次警報記錄」，不是固定頻率的感測器取樣，也不直接代表警報持續多久。兩筆記錄之間沒有資料，只能稱為記錄上的沉默區間，不能直接解讀為設備正常運轉。
